## jsprimer: 10 年目を迎える JavaScript の入門書を更新し続ける方法

### 目的

- TypeScript の前に JavaScript
- JavaScript は毎年更新され続けていて、それをどうやって追従しているかについて
- 書籍というものが、AI がある今にどうやって書き続けていくかについて

### 理由

- TypeScript は JavaScript に型をつけたものです
- なんで今書籍を更新している
- TS 5.8 で追加された"erasableSyntaxOnly"で象徴されるように、TS は型を取り除けばただの JavaScript です。
  - [https://www.typescriptlang.org/tsconfig/#erasableSyntaxOnly](https://www.typescriptlang.org/tsconfig/#erasableSyntaxOnly)
- また TypeScript の Design Goal として JavaScript と非互換な機能や変更を入れることはしないようになっています
  - [https://github.com/Microsoft/TypeScript/wiki/TypeScript-Design-Goals](https://github.com/Microsoft/TypeScript/wiki/TypeScript-Design-Goals)
- そうした場合において、TypeScript における JavaScript は重要で、Runtime において JavaScript ができないことが TypeScript できることは何もありません。

## インタビュー

### Q1: JSPrimer をスタートした当初の動機は何でしたか？10 年経った今も続けている理由と違いはありますか？

> そこで新しい JavaScript の書籍を作ろうという話が始まり、jsprimer は次のような目的で始まっています。

> 目的
> • 現代的な JavaScript について理解できるようにする
> • 「これ読んでおいて!」と渡せる書籍
> • ES2015/ES2016...と言うような新しいものが出てきた時に 取り組める素養を作る
> https://efcl.info/2020/04/27/jsprimer/

が動機ですね。

> JavaScript Primer は、JavaScript の基礎を学ぶための入門書です。 主な目的としては JavaScript 初学者が JavaScript を学べるようにするということがあります。
> 一方で、JavaScript の仕様である ECMAScript は毎年更新されています。 また、JavaScript の実行環境であるブラウザ、Node.js/Deno/Bun/Cloudflare Workers などは常に更新されていて、変化の激しい環境です。
> そのため、変化に対応できる基礎を身につけることが jsprimer の目的の一つです。
> https://efcl.info/2023/06/09/jsprimer-v2/

が更新し続けている理由ではあります。
変化に対応できるようにするためというのは同じかもしれません。

続けている理由は、この本を書くためのツールがあるからというのも一つの理由かもしれません。

textlint, honkit, doctest などはこの書籍とともに開発されています。

### Q2: 10 年間で最も難しかった技術的な課題は何でしたか？それをどのように解決しましたか？

- [ECMAScript 2024 の対応 · Issue #1706 · asciidwango/js-primer](https://github.com/asciidwango/js-primer/issues/1706)
- [ECMAScript 2023 の対応 · Issue #1658 · asciidwango/js-primer](https://github.com/asciidwango/js-primer/issues/1658)
- [ECMAScript 2022 の対応 · Issue #1337 · asciidwango/js-primer](https://github.com/asciidwango/js-primer/issues/1337)
- [ECMAScript 2021 の対応 · Issue #1220 · asciidwango/js-primer](https://github.com/asciidwango/js-primer/issues/1220)
- [ECMAScript 2020 の対応 · Issue #1145 · asciidwango/js-primer](https://github.com/asciidwango/js-primer/issues/1145)

第二版を出した時のレビュー対応と、ES2024 は Node.js の章をかなり書き換える必要があったのが大変でした。

ECMAScript/Javascript の範疇においては、基本的に毎年の更新はそこまで大きくはなく徐々にやってきます。
Node.js は意図的にライブラリやエコシステムの話が入ってしまうため、大きな変化が多かったです。

このライブラリを減らすというのは、書籍を書く時点でもかなり意識していたもので、TODO アプリの章とかにライブラリが出てこないのはこれが理由です。

### Q3: JavaScript の仕様更新に追いつくために、具体的にどのような仕組みや判断基準を設けていますか？

毎年、2 月ごとに ECMAScript の仕様が確定するので、このタイミングで蹴等しています。

```

スケジュール

    1月: 検討する
    2月 ~ 5月: 実装
    6月: ES2022の正式リリースと合わせて公開
        大体6月後半に News - Ecma International でリリースされる
        スナップショット(仕様が固まったかどうか)はReleases · tc39/ecma262を見るとわかる
```

何を入れるか入れないかは https://jsprimer.net/intro/ に書いている目的と目的ではないという部分を参考にしています。

```
本書の目的ではないこと

ひとつの書籍でJavaScriptのすべてを学ぶことはできません。 なぜなら、JavaScriptを使ってできる範囲があまりにも広いためです。 そのため、この書籍では取り扱わない内容（目的外）を明確にしておきます。

    他のプログラミング言語と比較するのが目的ではない
    ウェブブラウザについて学ぶのが目的ではない
    Node.jsについて学ぶのが目的ではない
    JavaScriptのすべての文法や機能を網羅するのが目的ではない
    JavaScriptのリファレンスとなることが目的ではない
    JavaScriptのライブラリやフレームワークの使い方を学ぶのが目的ではない
    これを読んだから何か作れるというゴールがあるわけではない

```

なんでも入れたくはなりますが、この目的外の部分を意識することで削ることができた話が多かったと思います。

### Q4: テキストコンテンツのテスト駆動開発とは具体的にどういうものですか？実例を挙げてください。

既知の言葉を使って未知のことを説明するということをかなり徹底しています。
そのため、ある用語がや概念が説明前に出てきてしまわないかというメタ的なテストは書いたりしています。

人間が持っているコンテキストはかなり小さいという前提にしていて、できるだけ既知 -> 未知という流れを意識しています。

### Q5: オープンソースのドキュメントプロジェクトとして、コントリビューターを増やし維持するコツは何だと思いますか？

Good First Issue や オンボーディングが大事だと思います。
できる人はアウトラインとか説明とか issue を書くとやってくれる可能性は感じました。
一方で、それだけだと手を出しにくいと思う人もいるので、オンボーディングやもっと違う面の工夫が必要だと思います。

typo の修正などはかなり多くの人がやってくれているので、これは次の章が大事だったんじゃないかなと思いっています。

- [文章の間違いに気づいたら · JavaScript Primer #jsprimer](https://jsprimer.net/intro/feedback/)

一方で、章の追加はやっぱり丁寧な説明が必要で、これはかなり難しいと感じています。
Open Collective などで資金を募ってこの辺を補強できるようにしていきたいです。

### Q6: 商業出版とオープンソースのコンテンツを両立させる上での葛藤や工夫はありましたか？

特にないです。最初からオープンソースでやるという前提でやっているので、商業出版との関係は特にないです。

### Q7: TypeScript が主流になる中で、なぜ JavaScript の基礎学習が重要だと考えていますか？

TypeScript は JavaScript に型をつけたもので、いきなり TypeScript を学ぶのは難しいと感じています。
そのため、まずは JavaScript の基礎を学ぶことが大事だと考えています。
この辺は今も変わらない話かなと思っています。

また React や Vue などのフレームワークを学ぶ上でも、独自の概念が多いですが実際に動いているのはただの JavaScript です。
この辺を魔法のように感じんじゃなくて、なぜそれが動くのかというのを理解するためにも JavaScript の基礎は大事だと思っています。
それを探求できるような仕組みを伝えたいというのも jsprimer の目的の一つです。

### Q8: AI によるコンテンツ生成が普及する時代に、人間が作る技術書の価値をどう考えていますか？

AI は自分が知っていることを知るにはかなり便利です。いわゆるサマライズや調査の代行といったできるが時間を節約する手段としては非常に有用です。

一方で、未知のことを適切に知るのは難しいことがあります。

> 注意点としては Transpiler や Polyfill は、あくまで既存の機能を用いて新しい機能の再現を試みているだけにすぎません。 そのため、既存の機能で再現ができないプロポーザル（機能）は Transpiler や Polyfill では再現できません。 また、完全な再現はできていないことがあるため Transpiler や Polyfill を新しい機能を学ぶために使うべきではありません
> https://jsprimer.net/basic/ecmascript/

にもありますが、AI が返すことはある種の Transpiler や Polyfill のようなもので、元の情報とは異なることがあります。
これら翻訳された情報を元に学ぶと間違った理解をしてしまうことがあるため、あくまでオリジンとなる情報を理解することは本質的に避けることが難しいです。

もちろん、ツールを使うことでより簡単に学べる、使えるという点はいてレーションを早くする上で重要なので、この心持ちを大事にしていきたいです。

### Q9: JSPrimer のようなプロジェクトを 10 年続けるために、精神的・経済的に持続可能にするコツは何ですか？

スケジュールはきっちり守りすぎないこと。jser.info もそうですが、ここを厳密にすると取り返そうと思って無理をしてしまいます。
jsprimer の更新は結構開発合宿とかをしてることが多いですが、こういった気分転換をして進めるというのは重要かなと思っています。

また、更新のプロセスというのはある種形を作っていくことで、継続がしやすくなります。
ここを気合いで解決しないで、プロセスを作っていくことが大事だと思っています。

### Q10: 発表で最も伝えたい、JSPrimer から学んだ教訓はなんですか？

- 既知を使って未知を説明すること。
- 書籍を書くこととソフトウェア開発に特に違いはないということ。
  - [Introduction | 技術文書をソフトウェア開発する話](https://azu.gitbooks.io/nodefest-technical-writing/content/)
  - 現代では AI 向けのプロンプトとして Design Doc を書いて開発するといった手法がかなり有効になってきていて、文章とソフトウェア開発はかなり近いものだと感じています。
  - 文章を書く場合でも、書いて、自分でレビューして、修正するというフローをよく取ります
  - これは現在だと、書いて、copilot-review などでレビューして、それを修正するフローとなったり、逆にレビューだけをするフローになったりする場合もあります。
  - コードを書くのと文章を書くのは、入力方法の違いぐらいなものと捉えてみると、もっと文章を書くのが面白くなるかもしれません。
