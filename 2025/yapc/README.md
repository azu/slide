# 技術的依存とは

**定義**：
- 自動化できる部分は自動化する
- ツールやシステムに頼る
- 再現可能なプロセス

**特徴**：
- スケールする
- 疲れない
- 複利効果を生む

---

# 心理的依存とは

**定義**：
- 「自分がやらなければ」というプレッシャー
- 完璧主義
- 義務感

**特徴**：
- スケールしない
- 疲れる
- 燃え尽きにつながる

---

# [fit] なぜこのバランスが重要か


<!-- 技術的依存と心理的依存の2軸グラフ：右下（技術的依存高、心理的依存低）が持続可能ゾーン -->

**技術的依存が高い**
→ 長期的に継続できる

# JSer.info Policy

> **「技術的な嘘はつかない」**

**使わない言葉**：

**使う言葉**：

感情極性値 -0.216（ほぼ中立）

# 12の設計原則


[.column]
**読む技術（JSer.info）**：
1. データドリブンな公開基準
2. 退屈な部分だけ自動化
3. 小さなイテレーション

**書く技術（textlint）**：
4. デフォルトルールなし戦略
5. 最小コア、豊かなエコシステム
6. 検証可能なことを自動化
7. 最小限の依存関係

[.column]
**伝える技術（jsprimer）**：
8. Living Standard戦略
9. 既知→未知の原則
10. 自動テストによる品質保証
11. 透明な経済モデル
12. フィードバックループの設計
