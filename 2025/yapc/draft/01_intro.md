## Slide 4: 今日話すこと - 3つのプロジェクトの循環

### ビジュアル
- 3つのプロジェクトを円形に配置
- 読む・書く・伝えるの比率を視覚化（円グラフやバー）
- プロジェクト間の矢印で循環を表現

### コンテンツ

```
各プロジェクトに「読む・書く・伝える」がある

Part 1: JSer.info（10分）
読む70% / 書く20% / 伝える10%
├─ 情報収集の自動化と手動判断
├─ JSer.info Policy
└─ 「知ってもらう」哲学

Part 2: textlint（10分）
読む30% / 書く50% / 伝える20%
├─ Promise本からMCPまでの進化
├─ No core rules戦略
└─ AIベースライン時代の品質管理

Part 3: JavaScript Primer（12分）
読む20% / 書く30% / 伝える50%
├─ Design Docによる設計
├─ Living Standard戦略
└─ 100人との協働

Part 4: 循環の技術（10分）
複利効果と持続可能性の設計思想
```

### スピーカーノート
- 「今日は、これら3つのプロジェクトを通じて学んだ『読む技術・書く技術・伝える技術』についてお話しします」
- 「面白いことに、各プロジェクトには『読む・書く・伝える』の全てが含まれていますが、その比重が異なります」
- 「JSer.infoは読むことから始まりました。情報収集が70%を占めています」
- 「textlintは書くことが中心で、文章品質の自動化に50%を費やしています」
- 「JavaScript Primerは伝えることが重点で、100人以上との協働に50%のエネルギーを使っています」
- 「最後のPart 4では、これら3つのプロジェクトに共通する『循環の技術』、つまり15年間続けることで生まれた複利効果と、持続可能性の設計思想について

お話しします」
- 「それでは、Part 1のJSer.infoから始めましょう」
- 時間: 2分
